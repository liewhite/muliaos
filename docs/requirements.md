# muliao 功能需求

muliao 是跑在用户自己一台 Mac 上的个人多 agent 助手平台：用户在网页（电脑浏览器、iPhone 主屏应用）上和多个 agent 对话、派活、看进度；agent 能执行命令、读写文件、互相委派、定时醒来、在看板上协作，并能自己积累记忆与技能。只有一个用户。

本文只写系统要做什么、用户和 agent 看到什么行为，不写怎么实现。「必须」是硬要求，「应」是默认做法、有更好的办法可以换。

## 0. 总体要求

- **单用户、单机**：一个进程、一台机器、一份数据目录。为了架构简单可以牺牲一点边角体验，但不能出现不可恢复的错误（丢数据、重复执行已有副作用的操作、权限失控）。
- **数据可靠**：所有对话、运行进度、看板、触发器都持久化；服务随时可能被重启或被杀，重启后从停下的地方接着做，不丢、不重复对外动作。
- **数据库是唯一事实来源**：界面上的实时刷新只是加速，丢了刷新不影响正确性，页面重新拉取即可得到最新状态。
- **网络不可靠**：本机外网会间歇断 30 秒到几十分钟。对外请求（模型、推送、网页、语音）对暂时性失败要退避重试，长时间失败才算失败并让用户看见。
- **可观察**：失败要看得见（界面、通知、日志），不静默吞掉。
- **配置单一来源**：一个配置文件，未知的键启动即报错；程序不读环境变量。
- 界面与给 agent 的说明以中文为主。

## 1. 访问与登录

- 网页单用户密码登录；登录状态长期有效（约 90 天），改密码使所有已登录设备失效；可退出登录（同时取消本设备的推送订阅）。
- 连续输错密码按来源退避，防暴力猜测。
- 支持经反向代理用 HTTPS 外网访问；可作为 PWA 添加到 iOS 主屏。
- 响应按需压缩，减少手机外网流量。

## 2. Agent

- **建 agent**：名字（唯一、可改、不区分大小写形式，不能叫 `user`）、描述（它是干什么的，别的 agent 据此决定找谁）、模型、分组、角色、额外的允许/禁止规则。系统给每个 agent 一个不变的内部编号。新建时可预览它最终能用的工具和资源。
- **改**：上述字段都能改；改名不影响它的权限、资源归属与历史。
- **默认 agent**：至多一个，新会话默认选它。
- **归档 / 取消归档**：停用但保留全部数据；归档的 agent 不接新工作（新会话、委派、issue、触发器都投不进，并说明原因），只能在它空闲时归档。
- **删除**：不可撤销，它忙（在运行、在等后台任务/委派/唤醒）时拒绝；删除时清理它的会话、触发器、工作目录、私有资源，它名下仍被别人用着的资源转给平台，看板上它的指派与负责置空；用量与工作历史保留。删到一半服务重启要能接着删完。
- **agent 详情页**：配置、最终能用的工具与资源（及来自哪条规则）、记忆、工作目录浏览、工作历史、后台任务（可结束）。
- 每个 agent 有自己的工作目录。

## 3. 会话

### 3.1 会话与消息
- 会话属于一个 agent，来源有：用户新建、触发器、issue、委派（委派开出的是 thread，挂在发起会话下，用 agent + thread 名标识，同名即续聊）。
- 会话列表：按最近活动排序，运行中/等待中的置顶并标状态；按 agent 筛选；按关键字搜索（搜用户消息、回复和工具调用参数，不搜工具结果）；有未读标记。
- 用户可以给任何会话发消息（含 thread 和触发器开出的会话）；其他来源只能续写自己开出的会话。
- 消息支持附件（任意文件，图片可预览），先上传后引用；附件与会话独立保存，内容相同只存一份。
- 回复按 Markdown 渲染；只显示站内图片，外部图片显示成链接（防止经图片地址外带数据）。
- **实时展示**：模型的回答（含工具调用之间的文字）、工具调用与结果边生成边显示；工具结果按工具给出合适的展示（终端输出、代码、diff、表格等），认不出的显示原文；显示每步真实的起止时间。
- 会话页显示：排队中的消息、在等什么（后台任务、委派、唤醒、提问、等批准，可看日志、结束任务、停止 thread）、当前上下文大小与压缩阈值、用量累计、压缩点。
- 用户插话：运行中发来的消息在下一次请求模型前一起交给它，不必等运行结束。
- **停止**：会话不空闲时可停止（含排队、等待中的）。停止前已产生的内容（生成到一半的回答、已完成的工具结果）照常保存；它开出的委派 thread 一并逐层停下，它的后台任务被结束，等待中的项被放弃。
- **重试**：运行最终失败时会话页显示错误和「重试」按钮，重试从失败处接着跑。
- **手动压缩**：空闲时可手动压缩上下文。
- **删除会话**：忙时拒绝；它开出的 thread 保留；交给它的未完成委派以「被删除」回给发起方。
- 语音输入：按住麦克风录音，转写成文字放进输入框（中英混杂原样输出），录音不落盘；没配置转写服务时不显示按钮。

### 3.2 运行（agent 怎么干活）
- 会话收到消息/任务就开始一次运行：组装上下文，循环「请求模型 → 执行工具 → 再请求」，直到模型不再调用工具。
- 同一会话同时只有一次运行；不同会话、不同 agent 并发，不设总数上限；每个模型服务商有可配置的并发请求上限，所有 agent 共享，超出排队。
- **每一步都保存**：每次模型请求及其回复、每批工具结果都落库。服务重启、暂时失败后从上一步接着跑，已保存的不重放。
- **被打断的工具调用不自动重新执行**（副作用可能已经发生），而是给模型一个「被中断、没重新执行、可能已生效，先核实」的结果，由模型决定。
- **暂时性失败**（模型或外部服务一时不可用、限流、超时）退避重试（数秒起翻倍，单次最长约 5 分钟），约 30 分钟仍失败算最终失败；其余错误当场最终失败。最终失败通知用户。
- **给模型的上下文**：固定说明（agent 名、工作目录、会话来源的处理说明）+ 它能用的每块记忆全文 + skill 索引 + 自我进化守则；每次运行变化的信息（当前时间、回答交给谁、本次连接工具时的问题）单独放在本次新增的第一条请求里。固定部分在同一会话的多次运行间逐字节不变，以命中模型的提示缓存；Anthropic 协议总是打缓存断点。
- **上下文压缩**：上一次请求的输入超过全局阈值时，把较早的消息连同上一份摘要交给模型总结，之后用「摘要 + 最近若干步原文」继续；原始消息不删，界面仍显示全文并标出压缩点。长运行中途也能压缩。
- **模型**：写成 `<服务商>:<模型名>`，服务商在配置里定义，协议支持 Anthropic Messages 与 OpenAI Responses（含兼容服务）；界面上可实时向服务商查询模型列表。没有思考设置（#950）：不请求、不显示思考，老模型也能用；模型自己回的思考块原样存下、按协议要求回传，别家协议的不发。
- 图片附件和工具返回的图片在发给模型前按服务商限制处理（长图切段而非缩小），历史里保存原件，一张坏图不能让会话之后每次都失败。
- **回答交给谁**：用户在等的，回答完推送通知；委派来的，回答交回发起方；触发器开的默认不推送（agent 自己决定 `notify_user`）。
- 每次模型请求的 token 用量记账（输入、其中缓存读写、输出），记到 agent、会话与模型名下。

### 3.3 等待与异步工作
- agent 发起的异步工作（后台命令、带回报的委派、定时唤醒）期间会话处于「等待中」，结果回来自动接着做。
- 工作状态只有三种：运行中、等待中、空闲；全系统（会话列表、看板、触发器防重叠、thread 列表）用同一个判断。
- 异步工作可配心跳：每隔一段时间向发起会话投一条「还在进行」的检查消息（不推送），已有检查在排队就不重复投；没事可做时 agent 回一个约定的简短回复，界面把它收起。

## 4. agent 可用的工具

每个工具有清晰的参数说明（参数结构由类型生成），输入输出用模型熟悉的格式（带行号用 `cat -n` 格式，多段读取用 `head` 式标题，截断时单独一行说明怎么续读，结构化结果是一段 JSON）。参数写错时告诉模型哪个字段错了，让它改了重试（不回显参数值，以免带出密钥）；同一工具连续重试太多次提示换做法。外部服务暂时不可用时整次运行稍后重试；系统性错误让运行失败、让人看见。

- **文件**：`read_file`（行号、多段、图片直接看、超长分段续读）、`write_file`（新建或整体覆盖，自动建父目录）、`edit_file`（按原文唯一匹配或按行号+首行锚点替换，多处多文件一次改，任一失败全部不写，成功回显改动处）、`share_file`（把文件发给用户，在回复里显示）。文件工具与同一回复里其他调用保持先后顺序。
- **命令**：`run_shell`（前台必须给超时；或后台运行，立即返回任务号，输出写进工作目录日志，结束和心跳作为事件回到会话）、`job_status`、`job_kill`。命令在 agent 工作目录执行（环境变量 `MULIAO_WORKSPACE` 是这个目录，先 cd 到别处的命令也找得到它，如 ssh 配置按它找证书），可注入指定的 secret（输出里自动打码）。
- **skill 脚本**：`skill_run`（运行 skill 目录里的脚本；SKILL.md 声明要审批的脚本每次执行前等用户批准，用户可选「始终允许」同一调用）。
- **与用户交互**：`ask_user`（1–4 个选择题，总能填「其他」，只在用户在等时可用）、`notify_user`（推送通知）。
- **委派**：`delegate_task`（交给某 agent 的 thread，不等；默认回答推给用户，`report_back` 时回答作为事件交回自己）、`ask_agent`（等对方回答，作为工具结果）、`list_threads`、`stop_thread`。目标可以是自己（开一个新的自己做旁支任务）。
- **定时唤醒**：`wake_me`（一个会话至多一个，再约就替换，可取消）。
- **agent 管理**：`list_agents`、`get_agent`、`create_agent`、`delete_agent`。
- **secret**：`vault_set`（加密存入，值不进会话记录与日志）。
- **看板**：`issue_list`、`issue_show`、`issue_create`（可一次建一批互相依赖的）、`issue_update`、`issue_comment`、`issue_stop`。
- **触发器**：`trigger_kinds`、`trigger_list`、`trigger_create`、`trigger_update`、`trigger_run`、`trigger_delete`。
- **工作历史**：`history_append`、`history_search`、`activity_overview`（某天的活动汇总）、`session_read`（读一个会话的时间线，可按标签和正则筛选）。
- **网页**（配置了才有）：`web_search`、`web_fetch`（抓取服务失败时直连再抓一次）。
- **MCP**：agent 可用、已启用的 MCP server 的工具，名字带 server 前缀。
- 工具列表只由权限规则决定，不随运行状态增减（保护提示缓存）；需要运行状态的前提在调用时检查并说明原因。

## 5. AI 资源与权限

### 5.1 资源
- 种类：**记忆**（有长度上限的 Markdown：全局、角色共享、agent 私有）、**skill**（目录：SKILL.md 带名字和触发描述，加任意附件和脚本）、**MCP server**（连接配置，可引用 secret，可启用/停用，可试连列出工具）、**secret**（三个维度各选一项（#1069）：怎么保存——服务端主密钥加密、passkey 加密（只有用户的 passkey 能在浏览器里解开，agent 每次要用都等用户在界面上授权一次或一段时间，或拒绝，授权按 agent 隔离、只在服务内存里），或明文（#1093：不加密、界面直接显示与编辑，只能是口令，只有用户能建）；内容——口令，或密钥对（平台能用它签名，第一种是 SSH 短期登录证书）；能否取出明文——任意命令、只给 skill 脚本和 MCP（不能注入自写命令），或只能签名（只有密钥对能选）。签名在解开它的一方做：服务端保管的在服务端签，不等批准（只防误用：能读主密钥的程序仍能解开）；passkey 的在用户浏览器里签，每次等用户看着内容批准；网页由运行平台的机器提供，那台机器被攻破后能在用户下一次确认时拿走私钥）。
- 所有可编辑资源（含 agent 配置与权限规则）都是资源目录下的普通文件：人和 agent 可以直接用文件工具改，改完下次运行生效；资源变化时界面实时刷新。文件在谁的目录下就归谁；转移归属就是挪文件。
- 读坏的文件跳过不加载，在相关 agent 每次运行开头告诉它；权限规则文件写坏时整份不生效、沿用上一份有效的，平台拒绝再改它直到修好。
- 同名冲突：平台那份优先；两个 agent 同名的都不加载并报出。
- 平台自己写资源文件时校验写后内容（格式、记忆长度），不合格不写并说明原因；覆盖已有资源文件要求本次运行读过且之后没被改，防并发覆盖。界面编辑文件期间被别人改了，保存时冲突提示重来。
- 界面「AI 资源」页：按种类列出全部资源、归属、被谁使用；查看与编辑记忆、skill（含附件浏览、编辑 SKILL.md）、MCP、secret（加密的只能设值不能看值，明文保存的直接显示；passkey 加密的在浏览器里加密，页上方列出等授权的请求与生效中的授权）；转移归属；删除。
- 全局记忆总是存在、人人可读。

### 5.2 权限（分发）
- 规则形如 `动作:种类:名字通配`（动作 use/write，种类 tool/skill/mcp/secret/memory），另有「允许写本机某目录」的路径规则；allow/deny 两组，deny 优先。
- 角色是一组规则；内置 base（每个 agent 都有：全部非管理类工具、全局记忆、平台公开的资源）和 admin（全部工具、写全部）；可自建角色。agent 最终权限 = base + 各角色 + 自己的额外规则。界面「角色」页可建、改、删角色并预览效果；新规则至少要匹配一个现有的工具或资源。
- 资源的主人对自己的资源总能使用和修改。
- 权限只防误操作、省上下文，不是安全隔离。

### 5.3 写沙箱
- agent 的命令（前后台 shell、skill 脚本、触发器检查与常驻命令）、MCP 本地进程及所有子进程运行在操作系统沙箱里：只能写自己的工作目录、临时/缓存/工具链等常用目录、获授权的目录、自己有权改的资源文件；读、网络不限制。文件写工具按同一份可写范围检查。
- 被拦下时给原本的系统报错并补一句被什么拦、找谁授权。
- 平台私有文件（配置、备份、推送私钥）对非 admin 一律不可读写。
- 路径比较要按磁盘上的真实路径（macOS 不分大小写），防绕过。
- 计算可写范围遇到系统授权弹窗卡住时限时报错，不挂死。

## 6. issue 看板

- issue 字段：标题、描述（Markdown）、状态（backlog/in_progress/in_review/blocked/done/cancelled）、优先级、负责项目的 agent（owner，必填，不随指派变）、指派人（agent、用户或空）、上游依赖（无环，成环拒绝并指出环）、时间线（创建、评论、每个改动一条，只增不改，记下发生在哪个会话）。
- **投递**：in_progress、指派给 agent、上游都已完成（done 或 cancelled）时，每条新动态（他人的评论、改动、上游完成）投进该 agent 专门处理这个 issue 的会话（每个 issue+agent 唯一一个），只投一行摘要和本次动态；agent 在这个会话里自己做的改动不投回。
- 无人处理时用户的评论投给 owner。
- **停滞**：in_progress、指派 agent、不等上游、它的 issue 会话空闲 → 标「没人在处理」；issue 会话里一次运行结束后变成停滞时，请 agent 表态（做完、交给用户、或挂起等待）。
- **审核**：agent 做完设 in_review 指派用户；用户「通过」→ done，「打回」填理由 → 回到 in_progress 指派回交出它的 agent。通知里可直接通过/打回。只对当前指派给用户且未结束的有效，防过时操作覆盖。
- `issue_stop`：停掉正在做的会话再改状态，可附留言让它收尾或改方向。改状态本身不停工作。
- 一次可建一批互相引用的 issue（任一不合法全不建，建完才投递）。
- issue 会话最终失败只记一条动态，不自动重投。
- 界面：列表（按状态/指派/owner 筛选，显示停滞、等待上游、会话状态）、依赖图、详情（描述、依赖、被谁依赖、时间线、评论框、可点进相关会话）、新建与编辑、手动「开始」、删除。正文里的 `#数字` 链接到 issue。

## 7. 触发器

- 具名、属于一个 agent、带提示词、可启用/停用；每次触发新开一个会话，事件内容附在提示词后。
- 种类：**定时**（cron，按配置时区）、**一次性**（某时刻，到点后结束，留在「已结束」列表可查它开的会话）、**常驻流**（平台托管一条常驻命令，输出每行一个事件；退出指数退避重启；事件防抖合并；上一次会话没做完就排队，不重叠、不丢、内存有界；stderr 写日志文件并轮转）。
- **前置检查**：触发前先跑一条命令（有时限），「有输出才触发、输出作为事件」或「输出变了才触发、附 diff」；检查失败或常驻命令连续失败记为脚本故障，正常→故障时开一个会话通知所属 agent 去修（投不进就推送用户），恢复后清除。
- **防重叠**：上一次触发开的会话还没做完就跳过本次并计数显示；挡路的会话在等待时通知用户一次。停机期间错过的定时只补一次，停用期间的不补。
- 立即运行（不消耗一次性的那次）；改、删；界面显示下次触发时间、最近一次会话、跳过次数、故障。
- agent 归档时：定时跳过，一次性推送用户说没做，流式事件丢弃。

## 8. 通知与推送

- 通知：标题、正文、点开去哪、未读。来源：用户在等的回答完成或在提问/等批准、运行最终失败、`notify_user`、看板交给用户、触发器挡路或故障兜底、测试。
- 通知收件箱页，未读数即应用角标；打开对应页面即标已读。会话的未读 = 有指向它的未读通知。
- Web Push（VAPID，加密载荷），每台设备独立投递、暂时失败退避重试约 30 分钟，设备失效（404/410）删订阅；点通知打开对应页面（iOS 主屏应用冷启动也要能跳过去）；issue 交审的通知带「通过/打回」操作。
- 设置页：开启/重新订阅本设备推送、发测试通知。

## 9. 工作历史与用量

- **工作历史**：agent 记下的「做过的事」（日期、标题、摘要、引用、重要程度），只能追加不能改删，删 agent 也保留；支持中文关键字检索（按相关度）和按日期、agent、重要程度列出；agent 详情页可看。
- **活动回顾**：按天汇总某 agent（或全部）的活跃会话、用户说过的话、对 issue 的操作、失败的运行和当天历史；读单个会话时间线。用户说的话只按真实发送方认。
- **用量页**：按 agent、模型、天（按配置时区）汇总 token，输入里注明缓存读、写各多少；只增不改。

## 10. agent 页面

- agent 可在工作目录写网页（`site/<页面>/index.html` 及附件），界面「页面」列出全部、内嵌打开。
- 页面能跑脚本，但不能拿到登录 cookie、不能调平台接口（与界面隔离）；页面及其文件用签名链接访问。
- 平台不运行 agent 的服务，页面的实时数据由触发器或脚本写文件、页面轮询。

## 11. 工作目录与文件浏览

- 界面可浏览 agent 工作目录与 skill 目录、查看文件；下载的文件一律按不可信内容处理（不在本站执行，只有常见图片内联显示）；路径不能走出目录。

## 12. 设置与管理界面

- 设置页：推送开关与测试、脚本「始终允许」列表（可撤销）、退出登录。
- 管理菜单：agent、角色、触发器、AI 资源、页面、用量。
- 界面整体：电脑与手机两种布局、暗色模式、列表+详情；编辑表单不被实时刷新冲掉，只提交改过的字段，不覆盖别人同时改的其他字段。
- 页面在后台超过一分钟断开实时连接，回到前台重连并重新拉取。

## 13. 配置、日志、运维

- 配置文件（TOML）项：数据目录、资源目录、时区、日志（级别、文件、按大小轮转份数）、监听地址与端口、对外地址、登录密码与签名密钥、vault 主密钥、推送联系方式、模型服务商（协议、key、地址、并发上限）与默认模型、网页工具、语音转写、运行参数（压缩阈值、保留步数、记忆上限、前置检查时限、工具输出上限、上传大小上限）。缺必填项或主密钥不对拒绝启动。
- 出站 HTTP 遵循 macOS 系统代理设置（含例外列表）。
- 单实例：同一份数据已有进程在跑就退出。
- 启动时：确保全局记忆存在、接着删没删完的 agent、收掉上次没收尾的后台任务（标为被中断并告诉 agent，不盲杀）、续跑会话、启动触发器、监听资源目录。关停时：断开实时连接、停触发器与常驻命令、结束后台任务（标被中断），在跑的运行下次接着跑。
- 由 launchd 托管、自动重启；安装、切换版本、回滚有脚本，保留最近几个版本；部署后有自检（进程是新的、版本对、日志无 ERROR、端口通、不循环重启）。
- 程序签名固定，方便在系统设置里一次性授予完全磁盘访问。
- 提供接口描述导出（前后端契约）。
- 数据库结构随版本自动升级，失败整次回滚；库比程序新时拒绝启动。

## 14. 安全

- secret 只在 vault（加密），值不出现在会话记录、日志、界面、错误信息里；注入命令的 secret 在输出中打码。没有读 secret 明文的工具。
- agent 写的文件（含页面）都按不可信内容对待。
- 外部内容不当指令执行（约定，写在说明里）。

## 15. 本次重写特有：迁移与并行运行

- 一次性迁移工具：只读地把现有 muliao 的数据（数据库里的 agent、会话与全部消息、运行记录、看板、触发器、通知、工作历史、用量、文件、推送订阅、脚本授权；资源目录；工作目录；推送私钥）复制并转换到新的数据目录（`~/.muliao-scala`），不改原目录。
- 迁移进来的触发器开关照搬旧版（#881：正式切换时先停旧版再迁移，不会两个版本同时触发对外动作）。
- secret 只复制加密文件，值不解密打印。
- 新版本用独立端口、独立 launchd 服务名、独立数据目录与配置，与现有版本同时运行、互不影响。
